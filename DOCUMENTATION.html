📌 1. Executive Summary & Application Overview

The Hotel Autonomous Revenue AI Agent (KESH) is a production-grade, multi-tenant revenue management platform designed to replace manual revenue spreadsheets and static rule engines with an autonomous, self-learning AI agent.

Unlike legacy RMS software that simply outputs flat tariffs, KESH features a Single Autonomous ReAct Agent Loop augmented by a 3-Tier Memory System, Deterministic Safety Clamps, Live Google Hotel Competitor Web Scraping, and a Hybrid Semantic Vector RAG Engine.

🛡️ Hard Safety Guardrails

Every dynamic rate is strictly bounded between property floor/ceiling limits with hard ±20% single-day change clamps.

🔍 Transparent Reasoning

All rate shifts provide human-readable audit explanations tracking pace, city events, weather, and competitor gaps.

⚡ Zero Fragility Architecture

Replaces brittle multi-agent communication networks with a robust, tool-augmented single ReAct orchestrator.

🏗️ 2. End-to-End System Architecture

⚙️ 3. Core Modules & Subsystems

3.1 Single ReAct Agent Orchestrator & Memory Manager

Primary Implementation: backend/app/agents/orchestrator.py

The ReAct (Reasoning + Acting) loop evaluates natural language user questions and autonomous system triggers. Instead of making generative assumptions, KESH executes registered tools to gather real-time data from SQL and live web sources.

  • Short-Term Dialog Memory: Retains rolling 20 conversation turns to resolve pronouns and follow-up requests.
  • Operational Memory: Loads verified property capacities, master room allocations, floor tariffs, and active competitor sets.
  • RAG Semantic Memory: Semantic embeddings matching hotel policy documents, cancellation rules, and official website pages.
  • Strict Temporal Filtering: Bounds calendar inquiries to exact month/year windows (e.g., "November holidays" strictly bounds Nov 1 – Nov 30).

3.3 Hybrid Semantic Vector RAG Engine & Crawler

Primary Implementation: backend/app/rag/vector_store.py & embeddings.py

The RAG engine indexes unstructured hotel documents, PDF standard operating procedures (SOPs), and crawls official hotel websites. It implements a hybrid similarity scoring algorithm: 

Score = 0.50 * CosineSimilarity + 0.35 * LexicalOverlap + ConceptBoost - OffTopicPenalty + PropertyAffinity
  • Domain Concept Clusters: Projects words into specialized concept embeddings (amenities, dining, rooms, pricing, holidays, policies).
  • Cross-Topic Filtration: Queries for hotel facilities (e.g. "swimming pool", "wifi") penalize holiday records to avoid irrelevant matches.
  • Structured Points Presentation: Results are tokenized and rendered as individual, highlighted specification cards.

3.4 5-Stage Autonomous Pricing Pipeline

Primary Implementation: backend/app/pricing/engine.py

Stage Signal Category Mathematical Formulation
1. Occupancy & Pace Pace Velocity Pace > 1.25x baseline → +10% to +25% surge; Slow pace → base baseline.
2. Competitor Positioning Market Index Maintains target 3-7% gap relative to market rival median without price war spirals.
3. Event & Holiday Multipliers Local Demand Diwali / New Year (1.40x), Corporate Conferences (1.20x), Off-Peak (1.00x).
4. Weather & Macro Modifiers External Signals Heavy rain warnings apply a 0.95x dampening modifier on leisure demand.
5. Deterministic Guardrails Safety Clamping Rate = clamp(Rate, Floor, Ceiling) with maximum ±20% change clamp.

🗄️ 4. Database Schema & Data Models

The system uses SQLAlchemy ORM supporting SQLite (embedded demo mode) and Microsoft SQL Server 2022 / PostgreSQL (production mode).

🏨 Core Property Models
  • hotels: Master property configurations, star rating, city, currency, and rate bounds.
  • room_types: Room categories (Deluxe, Suite, Standard), base tariffs, and room counts.
  • inventory: Daily date records tracking total, booked, available, and sellable rooms.
  • reservations: Ingested guest booking records, ADR, length of stay, and source channel.
📊 Intelligence & Audit Models
  • competitor_hotels & competitor_rates: Rival properties and live scraped rates.
  • pricing_recommendations: Recommended rates, confidence scores, reasons, and approval status.
  • agent_runs & agent_tool_calls: Complete audit logs of LLM thoughts and execution times.
  • audit_logs: Immutable enterprise audit ledger with actor IP, timestamp, old and new values.

💻 6. Frontend Architecture & User Interface

The frontend is built with React 18, TypeScript, Vite, and Tailwind CSS, engineered with sleek dark-mode glassmorphism, glowing telemetry indicators, and responsive charts.

🤖 AI Assistant Interface

Features multi-session chat persistence per hotel, visual tool-execution chips with exact millisecond latencies, and structured recommendation cards with approval action buttons.

Displays single-line stay dates, formatted multi-day price paths for both main hotel and competitors, and multi-tier demand badges (Corporate Midweek vs. Weekend Peak).

🔒 7. Security, Auditing & Role-Based Access Control (RBAC)

The system enforces enterprise security standards throughout all data access paths:

  • Role Permissions: Super Admin, Administrator, Revenue Manager, Pricing Analyst, and Read-only Auditor.
  • Tenant Isolation: Every request validates hotel_id ownership against the authenticated user's assigned property IDs.
  • Cryptographic Password Hashing: Passwords hashed with Bcrypt via Passlib.
  • Security Response Headers: Strict Content-Security-Policy, X-Frame-Options, X-Content-Type-Options, and Referrer-Policy.
  • Immutable Audit Logging: Sensitive events (price approval, floor override, document indexing) record user IP, timestamp, and diffs.
